ARCHITECTURE GÉNÉRALE
─────────────────────
Le générateur place des copies d'une forme atomique sur une grille,
à l'intérieur du masque de texte. Le circuit complet est :

  1. L'utilisateur sélectionne une shape via les boutons dans #shape-selector (index.html)
  2. updateBaseShape() injecte la shape comme <symbol id="base-dot"> dans les <defs> du SVG
     → utilisé pour l'aperçu en direct (les <use> dans le SVG de sortie)
     → lit directement SHAPES[] — aucune modification de la fonction nécessaire
  3. shapeDotSVG() génère les éléments SVG natifs (circle, rect, polygon…)
     → utilisé pour l'export SVG (pas de <use>, formes directement éditables)
     → doit être mis à jour pour chaque nouvelle shape (voir ANATOMIE ci-dessous)
  4. export-otf.js convertit les mêmes positions en paths opentype.js
     → utilisé pour l'export OTF


LE DOSSIER clone/
─────────────────
Les fichiers SVG dans clone/ sont des fichiers de référence dessinés dans Inkscape.
Ils ne sont PAS chargés dynamiquement par le navigateur.
Leur rôle : conserver la source de dessin pour chaque shape active.

  clone/circle.svg      → cercle noir plein
  clone/pink_square.svg → carré magenta (#ff00ff)
  clone/polygone.svg    → pentagone (sommet en bas, base en haut)
  clone/polygone8.svg   → octogone
  clone/trait_2.svg     → rectangle fin paysage (largeur >> hauteur)

  clone/archives/       → shapes retirées (conservées pour référence)
    darkblue_circle.svg, heart.svg, stars.svg, circle_outline.svg,
    ellipse.svg, outline.svg, trait.svg


EXTRAIRE UN VIEWBOX PROPRE DEPUIS INKSCAPE
──────────────────────────────────────────
Les SVGs Inkscape utilisent des coordonnées absolues (offset de page + calque).
Il faut les normaliser avant de les utiliser dans le code.

Méthode :
  1. Dessiner la forme dans Inkscape
  2. Fichier > Propriétés du document > Redimensionner la page au dessin
     → la page colle exactement à la forme ; les coordonnées deviennent relatives à (0, 0)
  3. Dans l'éditeur XML (Ctrl+Maj+X), lire width et height sur l'élément <svg>
     → ces valeurs donnent les dimensions du viewBox
  4. Le viewBox à utiliser dans le code : "0 0 W H"
     (arrondir à 3 décimales maximum, ou à l'entier si c'est propre)
  5. Réécrire le contenu de la forme avec des coordonnées propres depuis (0, 0)
     → ne pas copier le contenu brut d'Inkscape (transform="translate(...)" pollué)

Exemples des 5 shapes actives :

  circle.svg
    width="1.9135373mm" height="1.9135373mm"
    → viewBox dans le code : "0 0 2 2"  (arrondi à l'entier)
    → contenu normalisé : <circle cx="1" cy="1" r="1" fill="#000000"/>

  pink_square.svg
    width="2mm" height="2mm"
    → viewBox dans le code : "0 0 2 2"
    → contenu normalisé : <rect x="0" y="0" width="2" height="2" fill="#ff00ff"/>

  polygone.svg
    width="2.8294549mm" height="2.6909716mm"
    → viewBox dans le code : "0 0 2.829 2.691"
    → contenu normalisé : <polygon points="1.415,2.691 0,1.663 0.540,0 2.289,0 2.829,1.663"
                                   fill="#000000"/>

  polygone8.svg
    width="2.314mm" height="2.314mm"  (boîte carrée)
    → viewBox dans le code : "0 0 2.314 2.314"
    → contenu normalisé : <polygon points="0.348,0.353 0.012,1.163 0.348,1.973 1.158,2.309
                                           1.968,1.973 2.304,1.163 1.968,0.353 1.158,0.017"
                                   fill="#000000"/>

  trait_2.svg
    width="3.6135399mm" height="1.0272721mm"
    → viewBox dans le code : "0 0 3.614 1.027"
    → contenu normalisé : <rect x="0" y="0" width="3.614" height="1.027" fill="#000000"/>

Règle du preserveAspectRatio="xMidYMid meet" :
  Le symbole est toujours contraint par le côté le plus court de la cellule.
  Une forme large (trait_2) s'adapte en width, une forme haute s'adapte en height.
  Les ratios du viewBox définissent directement les proportions visuelles du dot.


CALCUL DES RATIOS DE FORME
───────────────────────────
Toutes les fonctions de rendu reçoivent r = demi-taille du dot (rayon ou demi-largeur).
Les dimensions réelles s'obtiennent depuis le viewBox par la règle xMidYMid meet.

La cellule du dot est carrée (size × size). Avec meet :
  scale = size / max(vbW, vbH)    ← le plus grand côté du viewBox est le côté contraint

  → demi-largeur rendue = (vbW / 2) × scale = r × (vbW / max(vbW, vbH))
  → demi-hauteur rendue = (vbH / 2) × scale = r × (vbH / max(vbW, vbH))

Exemples :
  circle   viewBox 0 0 2 2       → max = 2 → demi-largeur = r, demi-hauteur = r
  polygone viewBox 0 0 2.829 2.691 → max = W = 2.829
             → demi-hauteur = r × (2.691 / 2.829) ≈ r × 0.951
  trait_2  viewBox 0 0 3.614 1.027 → max = W = 3.614
             → demi-hauteur = r × (1.027 / 3.614) ≈ r × 0.284
             (dans le code : h = size × 1.027 / 3.614 — même résultat)
  diamond  viewBox 0 0 2 2.6     → max = H = 2.6
             → demi-hauteur = r × (2.6 / 2.6) = r × 1.0
             → demi-largeur  = r × (2 / 2.6)   ≈ r × 0.769
             ATTENTION : si H > W, c'est H qui est contraint, pas W.
             La largeur devient inférieure à r, la hauteur vaut r exactement.

Formule générale pour un sommet de polygon (px, py) dans un viewBox "0 0 vbW vbH" :
  offset_x = (px - vbW/2) × scale  où scale = r × 2 / max(vbW, vbH)
  offset_y = (py - vbH/2) × scale
  → sommet rendu = (cx + offset_x, cy + offset_y)

  Exemple avec le sommet bas de polygone (px=1.415, py=2.691), vbW=2.829 contraint :
    scale = r × 2 / 2.829
    offset_x = (1.415 - 1.415) × scale = 0             → cx
    offset_y = (2.691 - 1.346) × scale = 1.346 × scale ≈ r × 0.951   → cy + r×0.951


ANATOMIE DE shapeDotSVG()
──────────────────────────
Cette section décrit la structure de la fonction pour que tu puisses y ajouter
ou modifier un case sans avoir à deviner les conventions.

Signature : function shapeDotSVG(cx, cy, r)
  cx, cy  — coordonnées du centre du dot dans le SVG de sortie (pixels)
  r       — demi-taille finale du dot (après tous les multiplicateurs de taille)

Variables locales pré-calculées en haut de la fonction (disponibles dans chaque case) :
  const size = r * 2    → diamètre / côté pleine largeur
  const x    = cx - r   → bord gauche du dot (coin haut-gauche pour un rect carré)
  const y    = cy - r   → bord haut du dot   (coin haut-gauche pour un rect carré)

La fonction est une série de if/return — un bloc par shape — suivis du default circle.
Chaque bloc retourne une string SVG avec les coordonnées calculées depuis cx, cy, r.
Ajouter le nouveau bloc juste avant le commentaire "// Default: circle" (ligne 321).

── PATRON A — rect carré (viewBox W == H) ──────────────────────────────────────
  Utiliser x, y, size directement.

  if (currentShape === 'square') {
    return `<rect x="${x.toFixed(2)}" y="${y.toFixed(2)}"
                  width="${size.toFixed(2)}" height="${size.toFixed(2)}" fill="#ff00ff"/>`;
  }

── PATRON B — rect non carré (viewBox W ≠ H) ───────────────────────────────────
  Le côté le plus grand du viewBox détermine scale ; l'autre côté est réduit en proportion.
  Le rect rendu a toujours une dimension = size et l'autre < size.
  Il faut recentrer le rect sur cy (ou cx si c'est la hauteur qui est pleine).

  Exemple : trait_2 (viewBox 0 0 3.614 1.027) — W > H → W est contraint.
    size correspond à la largeur (côté contraint).
    Hauteur rendue : h = size × (vbH / vbW) = size × (1.027 / 3.614)
    Décalage vertical pour recentrer : oy = (size - h) / 2

    if (currentShape === 'trait_2') {
      // viewBox 0 0 3.614 1.027 — width-constrained. Height = size * (1.027/3.614).
      const h  = size * 1.027 / 3.614;
      const oy = (size - h) / 2;        // vertical centering offset
      return `<rect x="${x.toFixed(2)}" y="${(y + oy).toFixed(2)}"
                    width="${size.toFixed(2)}" height="${h.toFixed(2)}" fill="#000000"/>`;
    }

  Si H > W (forme haute plutôt que large), c'est la hauteur qui vaut size :
    Largeur rendue : w = size × (vbW / vbH)
    Décalage horizontal : ox = (size - w) / 2
    Utiliser x + ox pour le x du rect, et y pour le y.

── PATRON C — polygon ──────────────────────────────────────────────────────────
  Calculer chaque sommet depuis le centre (cx, cy) avec la formule de la section
  CALCUL DES RATIOS DE FORME.
  L'ordre des points suit le sens des aiguilles d'une montre en coordonnées SVG (Y-down).

  Exemple : diamond (viewBox 0 0 2 2.6) — H > W → H est contraint.
    scale = r × 2 / 2.6
    demi-hauteur = r × (2.6/2.6) = r × 1.0 = r   (côté contraint → ratio = 1)
    demi-largeur = r × (2/2.6)   ≈ r × 0.769

    if (currentShape === 'diamond') {
      // viewBox 0 0 2 2.6 — height-constrained. hw = r * (2/2.6), hh = r * 1.0.
      const hw = r * (2 / 2.6);    // horizontal half-width
      const hh = r;                 // vertical half-height (= r, constrained side)
      const pts = [
        `${cx.toFixed(2)},${(cy - hh).toFixed(2)}`,      // top
        `${(cx + hw).toFixed(2)},${cy.toFixed(2)}`,      // right
        `${cx.toFixed(2)},${(cy + hh).toFixed(2)}`,      // bottom
        `${(cx - hw).toFixed(2)},${cy.toFixed(2)}`       // left
      ].join(' ');
      return `<polygon points="${pts}" fill="#000000"/>`;
    }

  Démarche générale pour un polygon :
    1. Identifier le côté contraint : max(vbW, vbH)
    2. Pour chaque sommet (px, py) du viewBox :
         offset_x = (px - vbW/2) × (r × 2 / max(vbW, vbH))
         offset_y = (py - vbH/2) × (r × 2 / max(vbW, vbH))
         → `${(cx + offset_x).toFixed(2)},${(cy + offset_y).toFixed(2)}`
    3. Nommer les constantes intermédiaires avec des noms lisibles (h, hw, vm, hh…)
       plutôt que d'inliner les formules dans chaque point.

  5a. Ajouter la fonction polygone Clipper (mode dots qui se chevauchent)
      après getPolygone8Polygon(), vers la ligne 109 :

        // Returns a CCW polygon for a diamond (rhombus) in Y-up font coordinates.
        // viewBox 0 0 2 2.6 — height-constrained; hw = r*(2/2.6), hh = r.
        function getDiamondPolygon(cx, cy, r) {
          const hw = r * (2 / 2.6);
          const hh = r;
          return [
            { X: Math.round(cx        * CLIPPER_SCALE), Y: Math.round((cy + hh) * CLIPPER_SCALE) }, // top
            { X: Math.round((cx + hw) * CLIPPER_SCALE), Y: Math.round(cy         * CLIPPER_SCALE) }, // right
            { X: Math.round(cx        * CLIPPER_SCALE), Y: Math.round((cy - hh) * CLIPPER_SCALE) }, // bottom
            { X: Math.round((cx - hw) * CLIPPER_SCALE), Y: Math.round(cy         * CLIPPER_SCALE) }, // left
          ];
        }

      Winding CCW en Y-up : top → right → bottom → left.
      (Si les dots ne s'unissent pas correctement, inverser l'ordre des points.)

  5b. Ajouter la fonction path direct opentype.js (mode non-chevauchant)
      après addPolygone8Bezier(), vers la ligne 174 :

        // Appends a diamond (rhombus) to an opentype.Path, CCW in Y-up.
        // viewBox 0 0 2 2.6 — height-constrained; hw = r*(2/2.6), hh = r.
        function addDiamondBezier(path, cx, cy, r) {
          const hw = r * (2 / 2.6);
          const hh = r;
          path.moveTo(cx,      cy + hh);  // top
          path.lineTo(cx + hw, cy);       // right
          path.lineTo(cx,      cy - hh);  // bottom
          path.lineTo(cx - hw, cy);       // left
          path.close();
        }

        }

  5d. Ajouter dans le bloc canOverlap (polygon mode), vers la ligne 420 :

        }

MODIFIER UNE SHAPE EXISTANTE
─────────────────────────────
  1. Archiver l'ancien SVG dans clone/archives/ (ne pas supprimer)
  2. Redessiner dans Inkscape → sauvegarder dans clone/ avec le même nom de fichier
  3. Extraire le nouveau viewBox et le contenu normalisé (voir section ci-dessus)
  4. Mettre à jour l'entrée dans SHAPES (viewBox + content)
     → updateBaseShape() se met à jour automatiquement depuis SHAPES[]

  5. Mettre à jour shapeDotSVG() — recalculer les ratios depuis le nouveau viewBox
     Localiser le bloc if (currentShape === 'nom') dans shapeDotSVG(), vers la ligne 282.
     Appliquer la formule de la section CALCUL DES RATIOS DE FORME avec les nouvelles valeurs.

     Exemple — polygone change de viewBox "0 0 2.829 2.691" → "0 0 3.0 2.8" :
       Avant  : côté contraint = W = 2.829  → h = r × (2.691/2.829) ≈ r × 0.951
       Après  : côté contraint = W = 3.0    → h = r × (2.8/3.0)     ≈ r × 0.933
       Dans le code, remplacer :
         const h = r * 0.951;   →   const h = r * (2.8 / 3.0);
       Faire de même pour tous les ratios du bloc (hw, vm, hh…).

     Pour retrouver tous les ratios existants sans les recalculer depuis zéro :
       ils sont déjà nommés dans le case courant — les lire, puis recalculer
       uniquement ceux qui changent avec le nouveau viewBox.

  6. Mettre à jour export-otf.js : recalculer les ratios dans getXxxPolygon()
     et addXxxBezier() — mêmes formules, mêmes ratios qu'à l'étape 5.

  7. Mettre à jour le bouton dans index.html (SVG d'aperçu)
